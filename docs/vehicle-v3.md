# Vehicle V3 — confirmed distance and compact UI

Fuel saves independently of consumption. A closing Full has a pending incoming interval until a user confirms Trip A/manual distance or expressly chooses the odometer delta and confirms it. Starting Full liters are excluded; intermediate Partial fills and the closing Full are included. Monthly economy is weighted by liters, attributed to the closing Full date, and excludes unconfirmed/uncertain cycles. All-period weighted economy remains in the concise summary. Actual distance can be corrected later.

The confirmation is stored on the closing FuelEntry with start boundary ID, source and confirmation timestamp. Endpoint date/vehicle/classification changes invalidate affected confirmations. Odometer changes invalidate only odometer-based confirmations; partial edits/deletion recompute liters without discarding a valid measured period. Reconstructing changed pairs permanently clears obsolete confirmations. Stable date/createdAt/id ordering handles out-of-order entries. No legacy kilometers are promoted automatically; original values remain in optional history details and exports. Optional onboard average remains informational in advanced fields. Fuel forms have a retry-stable request ID so rapid double submit or retry cannot duplicate a saved transaction.

Washes and Maintenance share compact tiles. All history/edit/delete actions and reminders remain in dialogs that mount records only when opened. Wash history supports all months and a month filter. Financial summaries and charts retain all source records, independent of any history display limit. Selected vehicle scopes every amount/history/chart; API ownership independently scopes all queries/mutations. Add/edit forms retain existing fields and navy/gold styling; normal phone widths use two columns, below 340px tiles can stack.

Expense categories use centralized muted CSS tokens. The six-month chart retains month selection and exposes category amounts through an accessible details list. Confirmed monthly economy retains exact two-decimal values and a no-data dash, with compact chart height. Oversized onboard comparison is removed from the main screen; historic readings remain in fuel details.

## Accounting correction
Calendar-month payments, one-time washes, maintenance, test fees and insurance annual cost / 12 retain the existing accepted total. The UI explicitly describes insurance allocation. Previously, cost/km divided *all month expenses* by a possibly incomplete measured portion of the month; that is not a period-aligned metric. It now remains a dash where full-month distance coverage cannot be established from date-only refuels. Known segment kilometers can still be read without claiming they represent a whole month. Consumption arithmetic is unaffected.

## Additive migration and rollback
`20261012160000_confirmed_fuel_distance` adds nullable start ID/source/timestamp/request ID and owner/vehicle/date indexes; it changes no saved amounts, classifications or historical distances. It is idempotent and registered in `scripts/deploy-schema.mjs`. FuelEntry now enables RLS and revokes direct anonymous/authenticated Data API grants, matching the existing VehicleExpense server-session access model. SBO's server database owner still accesses records through owner-scoped application queries; no client Supabase auth integration is introduced. A local audit confirmed that repeating the migration preserves record count, liters and payments. Test on a copy before deployment. For rollback, first export a backup including the new confirmation fields, restore the prior application commit, and leave the additive columns and protective permissions in place (preferred, preserves all confirmations). Only if schema removal is explicitly necessary, after backup remove the new indexes/columns manually; existing FuelEntry rows and historic actualDistanceKm are unaffected. Never run destructive rollback as part of normal deploy.
